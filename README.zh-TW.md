# IoT 人體區域網路（BAN）健康監測

> **僅為模擬，不是醫療器材。** 病人資料是合成的，警示門檻沒有經過臨床驗證，也沒有連接真實的數據機或感測器。

本專案是第 5 章「物聯網醫療系統的架構與應用概論」（圖 5.1、5.2）所描述系統的可執行原型：

```
BAN 感測器 ──► 樹莓派閘道器 ──► GSM 數據機（AT 指令）──► 雲端伺服器 + SQLite
 (血氧、血壓、   10 位元 ADC、門檻判斷、   簡訊：醫師／急救／家屬     儲存所有讀數、
  呼吸、心率、    防彈跳、合理性檢查、       （危急時）                警告推送到儀表板、
  體溫、血糖)     斷線暫存後補傳           HTTP：批次上傳讀數          查詢病人歷史
```

| 模組 | 對應章節 | 功能 |
|---|---|---|
| `vitals.py` | 5.5.1–5.5.6 | 警示門檻，每一項都註明出處。血氧、血壓、呼吸取自本章；心率、體溫、血糖依 NEWS2 和 CGM 共識，標示為「外部來源」 |
| `sensors.py` | 5.4、5.5 | 合成病人，附有真實事件標記（血氧下降、高血壓危象、低血糖等），以及探頭滑脫造成的假訊號 |
| `gateway.py` | 5.3、5.3.1 | 樹莓派邏輯：ADC、分級、`confirm_n` 連續確認（防彈跳）、變化率合理性檢查、危急時直接發簡訊、斷線暫存後補傳 |
| `gsm.py` | 5.3 | AT 指令驅動（`AT`、`AT+CSQ`、`AT+CMGF`、`AT+CMGS`、`AT+HTTP*`），傳輸層可替換。內建 SIM800 模擬器；`PySerialTransport` 用於真實數據機（未在硬體上測試） |
| `cloud.py` | 5.2、5.3.3 | 關聯式資料庫。正常資料只儲存；警告推送到醫師儀表板；記錄危急警示是否送達 |
| `rehab.py` | 5.7.4 | 共用復健設備的無衝突排程（先看優先順序，再看截止時間） |

## 結果（100 位病人、24 小時、seed 7；`python -m banmon sweep`）

| 設定 | 偵測到的危急事件 | 通知延遲 中位數／最大 | 誤報（其中危急） | 簡訊數 |
|---|---|---|---|---|
| 不防彈跳（`confirm_n=1`） | 108/108 | 7 / 26 分 | 3,079（650） | 2,286 |
| **預設（`confirm_n=2` + 合理性檢查）** | **108/108** | **7 / 26 分** | **1,433（5）** | **345** |
| GSM 中斷 2 小時 | 108/108 | 7 / **106** 分 | 1,433（5） | 345 |
| 上傳遺失 20 % | 108/108 | 7 / 26 分 | 1,433（5） | 345 |

* **防彈跳加合理性檢查很有效**：危急誤報簡訊從 650 則降到 5 則，而且沒有漏掉任何危急事件。代價是延遲中位數多約 2 分鐘。不防彈跳時，簡訊量多出約 6 倍。
* **斷線暫存後補傳**：即使上傳遺失 20 % 或中斷 2 小時，所有讀數（547,200 筆）都有保存。中斷期間的危急簡訊會排隊，等收訊恢復才送出。如果中斷可能更久，需要第二條通訊管道，例如 LoRa 或 Wi-Fi。
* **書中門檻造成「警報疲勞」**：剩下約 1,400 次誤報全部是「警告」等級。
  * 收縮壓／舒張壓佔 1,038 次，因為書中把超過 120/80 都視為危險訊號。
  * 呼吸佔 371 次，因為靜止呼吸接近 12 次／分的病人會反覆越過 12–20 的範圍。
  * 下一步應改為每位病人各自的基準值。
* 34 次警告事件中漏掉 1 次：一次輕微的血氧下降，一直貼著 95 % 的界線。

## 安裝與使用

```bash
cd D:\robot\iot-ban-health-monitor
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\python -m pytest                    # 24 項測試
.venv\Scripts\python -m banmon rules              # 列出門檻與出處
.venv\Scripts\python -m banmon run --patients 50 --hours 12
.venv\Scripts\python -m banmon sweep              # 產生上表（約 90 秒）
```

## 硬體檢查（詳見 `docs/device-review.md`）

* **SIM800 一類的模組只支援 2G**。台灣 2G 已在 2017 年關閉、3G 在 2024 年底關閉，所以請改用 LTE Cat-M1／NB-IoT 模組，例如 SIM7080G 或 BG95。這些模組同樣用 AT 指令，程式只需小幅修改。
* **建議加上加速度計／陀螺儀**（ADXL345、MPU-6050），用於跌倒偵測，以及在病人活動時暫停判讀，排除動作造成的假訊號。它是第 11 章 MEMS 裝置中唯一已商品化、且可直接使用的。
* **建議的感測器**：MAX30102（心率、血氧）、MAX30205（體溫）、藍牙血壓計。
* **第 11 章的植入式感測器**仍是研究原型。MEMS 給藥裝置不應連接到這個系統。

要接上硬體時，把 `Sim800Simulator` 換成 `PySerialTransport("/dev/serial0")`（`pip install .[serial]`），並把 `sensors.Patient` 換成真實感測器的驅動程式。這兩部分都還沒有在實機上測試。
